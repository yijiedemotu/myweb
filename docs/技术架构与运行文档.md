# 项目技术架构与运行文档

帮助你（或其他开发者）快速理解这个网站：**它是什么、用了什么、代码怎么组织、数据怎么存、页面怎么渲染、后台怎么写数据、以及怎么本地/线上运行**。

---

## 一、这是什么项目

一个个人作品展示 + 博客 + 简历的个人网站，**自带可视化后台** `/admin`，用来发布文章、管理作品和编辑个人资料。

- 前台：首页（精选作品 / 最新文章，两排卡片 + 分页）、作品页、文章页、归档页、关于（作者）页、RSS
- 后台：文章 / 作品 的增删改查、拖拽排序、精选与显隐开关、个人资料编辑、**一键导入**（粘贴 JSON / Markdown）

技术上是**单体全栈 Next.js 应用**：前台与后台共用一套代码、一个 Worker，数据存 **Cloudflare D1**（托管 SQLite）。

---

## 二、技术栈与选型

| 层 | 技术 | 为什么 |
| --- | --- | --- |
| 框架 | Next.js 16（App Router）+ React 19 + TypeScript | 一套全栈跑前后台，SSR/SEO 好，生态大 |
| 样式 | Tailwind CSS 4 | 原子化样式，自带深/浅色切换 |
| 数据库 | **Cloudflare D1**（托管 SQLite） | 单作者读写量小；无需自建数据库服务，事务与索引够用。Workers 运行时既没有文件系统也没有原生模块，D1 是官方绑定方案 |
| Markdown | marked + highlight.js | 文章/作品正文渲染 + 代码高亮 |
| 渲染 | 动态服务端渲染（`force-dynamic`）+ 少量客户端组件 | 内容改动即时生效，无需重打包 |
| 后端交互 | Server Actions（Next 服务端动作） | 后台写操作无需单独写 REST API |
| 会话 | HttpOnly Cookie + HMAC 签名 | 轻量后台登录 |

## 三、数据模型与存储

运行数据在 **Cloudflare D1**（`wrangler.jsonc` 里绑定名为 `DB`）。表结构与初始内容由
`migrations/` 下的 SQL 迁移文件负责，**运行时不再建表**（见 `lib/db.ts`）。

三张核心表：

```
profile(id=1, name, headline, avatar, email, location, intro, about, skills, links)
posts(slug PK, title, summary, body, date, updated, tags, published)
projects(slug PK, title, tagline, description, tech, url, repo, image,
         year, status, featured, visible, position)
```

- `tags / tech / skills / links` 以 JSON 文本列存储。
- `projects.visible` = 前台是否展示；`position` = 展示顺序（后台拖拽改它）。
- `posts.published` = 是否发布（false 即草稿，前台不显示）。

**种子机制**：出厂内容已固化进 `migrations/0002_initial_content.sql`（1 条资料 / 7 个作品 /
11 篇文章），由迁移执行时灌入。`data/seed/*.json` 是迁移前的可读来源，**运行时不读取**。

> 关键点：**数据层被封装成 `ContentRepo` 接口**（`lib/content.ts`）。所有页面只依赖该接口读写，想换成 PostgreSQL/别的库，只改 `lib/content.ts` + `lib/db.ts`，页面几乎不动。

## 五、一个请求是怎么“跑”起来的

以打开首页 `/` 为例：

1. 浏览器请求 → Next 服务端。
2. 页面是 **Server Component**（`app/page.tsx`），在服务器上直接 `await` 数据层：
   `content.readProfile() / listProjects() / listPosts(...)` → 读 D1。
3. 服务端把数据渲染成 HTML（首页的作品/文章还交给客户端分页组件显示）。
4. 响应返回浏览器；需要交互的部分（分页、搜索、主题）由**客户端组件**在浏览器里接管（hydration）。

**文章详情**：`app/blog/[slug]/page.tsx` 用 slug 查 `posts`，把 `body` 交给 `renderMarkdown()`：
`Markdown(marked) → HTML → dangerouslySetInnerHTML`，代码块会走 `highlight.js` 高亮，再配上 `globals.css` 里的 `.prose` 排版。

> 因为读库都在服务端且页面标记了 `force-dynamic`，所以**在后台改了内容，前台刷新即生效**，不用重新构建。

## 六、后台是如何工作的（写数据链路）

后台 `/admin` 下所有写操作走 **Server Actions**（`lib/admin-actions.ts`，文件顶部 `"use server"`）：

```
后台表单/按钮 → Server Action（服务端执行）→ content.xxx()（写 D1）→ redirect / refresh
```

- **登录**：`login()` 校验 `ADMIN_PASSWORD`，通过则写入一个 **HttpOnly Cookie**（值 = HMAC(密码)）。每个后台页（`(dashboard)/layout.tsx`）先 `isLoggedIn()`，不过则重定向到 `/admin/login`。
- **文章/作品的增删改查**：`savePost / saveProject / deletePost / deleteProject`。
- **排序 / 显隐 / 精选**：`reorderProjects(order)` 整体重排（拖拽）、`toggleProjectVisible`、`toggleProjectFeatured`、`moveProject`。
- **一键导入**：`importPosts / importProjects` 接收粘贴的 JSON（作品）或 Markdown/JSON（文章），自动生成唯一 slug、跳过已存在项，一次批量写入。
- 登录保护通过每个 action 开头的 `requireLogin()` 实现（防御性校验）。

> 前端拖动排序是**客户端组件**（`ProjectsManager.tsx`）先用本地顺序体验，再调用 `reorderProjects()` 落库并 `router.refresh()`。

## 八、如何本地运行

前置：Node ≥ 22.5（见 `package.json` 的 `engines`），`npm`。

```bash
# 1) 安装依赖
npm install

# 2) 配置后台密码
cp .env.example .env.local     # 然后改 ADMIN_PASSWORD

# 3) 把表结构与内容应用到本地 D1（首次、以及迁移文件变化后执行）
npm run db:migrate:local

# 4) 本地开发（next dev + 本地 D1）
npm run dev                    # http://localhost:3000 ，后台 /admin

# 5) 用与线上一致的 Workers 运行时验证
npm run preview
```

- 本地 D1 数据落在 `.wrangler/state/v3/d1`（由 `next.config.ts` 里的
  `initOpenNextCloudflareForDev()` 提供绑定）。
- 想重置本地数据：删掉 `.wrangler/state/v3/d1`，再重新 `npm run db:migrate:local`。

## 九、线上如何运行（简述）

线上是 **Cloudflare Workers + D1**，没有自建服务器。当前线上实际配置见
[`部署现状-Cloudflare.md`](./部署现状-Cloudflare.md)；部署步骤见
[`../DEPLOY_CLOUDFLARE_DASHBOARD.md`](../DEPLOY_CLOUDFLARE_DASHBOARD.md)（控制台版）
或 [`../DEPLOY_CLOUDFLARE.md`](../DEPLOY_CLOUDFLARE.md)（命令行版）。

一句话流程：

```
代码 push → Cloudflare 构建（npx opennextjs-cloudflare build）
→ 产出 .open-next/worker.js → wrangler deploy → 边缘运行，实时读 D1
```

**日常发文章不需要走这条流程** —— 直接在网站 `/admin` 后台改，前台实时生效。

## 十、常见定制点速查

- 站点标题 / 导航项：`app/layout.tsx`、`components/HeaderNav.tsx`
- 配色与正文排版：`app/globals.css`（CSS 变量 + `.prose` + `.hljs` 代码配色）
- 每页内容：对应 `app/**/page.tsx`
- 内容字段/表：改 `lib/types.ts`、`lib/db.ts`、`lib/content.ts` 后需重新构建
- 换数据库：只替换 `lib/db.ts` + `lib/content.ts`（保持 `ContentRepo` 接口）

## 十一、常见概念小结

- **Server Component / Server Actions**：跑在服务器上，可直接读数据库、更安全；后台写操作都用它。
- **客户端组件（`"use client"`）**：需要交互状态（分页、搜索、拖拽、主题）时使用。
- **`force-dynamic`**：关掉静态预渲染，让每次请求实时读库 → 后台改完前台立刻生效。
- **为什么内容改完不用重新构建**：因为前台在服务端实时读 D1（动态渲染），不是打包时写死的。
